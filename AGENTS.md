## Project Structure & Module Organization

Application code lives in `src/bookstore_api/`. Keep business entities and value objects in `domain/books/`, use cases and ports in `application/`, and SQLAlchemy adapters in `infrastructure/`. Keep domain and application code independent of FastAPI, SQLAlchemy, and Alembic. `main.py` hosts the FastAPI application; `config.py` manages settings.

Tests live in `tests/unit/`, `tests/specs/`, and `tests/integration/`; reusable in-memory adapters live in `tests/fakes/`. Database revisions belong in `migrations/versions/`. Container configuration lives in `Dockerfile` and `compose.yaml`.

## Build, Test, and Development Commands

Use Python 3.14 or newer and run commands from the repository root:

- `uv sync --frozen`: install locked dependencies, including development tools.
- `uv run uvicorn bookstore_api.main:app --reload`: run the API locally.
- `podman compose up --build -d`: build and start the API and MySQL.
- `uv build`: build distribution artifacts.
- `uv run pytest`: run the test suite.
- `uv run ruff check .` and `uv run ruff format --check .`: check lint and formatting.
- `uv run basedpyright`: check types.
- `uv run alembic upgrade head`: apply database migrations using configured settings.

## Coding Style & Naming Conventions

Use four spaces for Python and two for other files, UTF-8, LF endings, and a final newline. Ruff targets Python 3.14 with a 100-character line limit. Use `snake_case` for functions and modules and `PascalCase` for classes. Add type annotations; BasedPyright applies strict checks to domain and application code.

## Testing Guidelines

Use pytest with `test_*.py` files and `test_*` functions. Cover business rules with unit tests and use fakes for collaboration specifications. MySQL fixtures require `BOOKSTORE_TEST_DATABASE_URL` pointing to a database named `bookstore_test`. No numeric coverage threshold is configured. Add regression tests for behavior changes.

## Commit & Pull Request Guidelines

Recent commits commonly use scoped Conventional Commits, such as `feat(persistence): ...` and `test(books): ...`. Follow that pattern. Pull requests should describe behavior changes, link relevant issues, and report validation commands and results. Include migration and configuration impacts when applicable.

## Configuration & Agent Instructions

Keep secrets out of commits; use `.env.example` for configuration examples. Host MySQL uses port 3307; containers use `mysql:3306`. Review autogenerated migrations before applying them.

Prefer codebase-memory-mcp discovery: `search_graph`, `trace_path`, `get_code_snippet`, `query_graph`, then `get_architecture`. Fall back to text searches for literals, configuration, non-code files, or insufficient graph results.
